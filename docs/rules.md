# 判定规则

> 本文负责：文件名、标签完整性、文件名/标签一致性、重复、歌词、归档、报告的所有判定规则。
> 本文不负责：流程顺序（见 [workflow.md](workflow.md)）、命令行参数（见 [usage.md](usage.md)）、
> 阈值与扩展名的配置位置（见 [configuration.md](configuration.md)）。

每条规则只在一个模块实现；修改规则时改对应模块并补 `tests/` 用例。

## 1. 文件名规则

唯一实现：`core/naming.py`。

### 1.1 规范格式

```
<歌手> - <歌名>.<扩展名>
```

`is_canonical()` 要求文件名同时满足：能解析出歌手、能解析出歌名、包含 ` - `（空格-空格）。

### 1.2 解析

`parse_filename()` 的优先级：

1. 先按第一个 ` - ` 分割；
2. 没有 ` - ` 时按第一个 `-` 分割；
3. 都没有时歌手为空、整段作为歌名。

### 1.3 规范化

`canonicalize()` **只**在「恰好一个 `-` 且没有 ` - `」时把分隔符改成 ` - `：

| 原名 | 结果 |
|---|---|
| `周杰伦-晴天.flac` | `周杰伦 - 晴天.flac` |
| `AC-DC - Back.flac` | 不改（已经有 ` - `） |
| `A-B-C.flac` | 不改（多个 `-`，可能是名字本身） |

`format_filename()` 会清理 `\ / : * ? " < > |` 等非法字符，并按需拼接扩展名。

### 1.4 版本标记

`version_markers()` 从**括号内容**里识别版本类别：

| 类别 | 同义词 |
|---|---|
| `live` | live、现场、演唱会、concert |
| `remix` | remix、混音、dj、bootleg、rework |
| `instrumental` | instrumental、伴奏、karaoke、offvocal、纯音乐 |
| `acoustic` | acoustic、unplugged、不插电 |
| `demo` | demo、小样、session、outtake、未发行 |
| `cover` | cover、翻唱 |
| `feat` | feat、featuring、ft.、ft |

`version_key()` 保留这些标记，只去掉下载序号与其他无关括号：

| 输入 | 去重键 |
|---|---|
| `晴天` | `晴天` |
| `晴天 (1)` | `晴天` |
| `晴天 (Live)` | `晴天\|live` |
| `晴天（现场版）` | `晴天\|live` |

去重键由 `Track.key` 使用，因此 Live/Remix/伴奏版不会因为名字相似被直接当成同一首。

## 2. 标签完整性

唯一实现：`core/tags.py: missing_tag_fields()`。

检查五个字段：歌曲名、歌手、专辑、年份、封面。返回缺失项的中文名列表。

严重级别只在检查阶段使用：

| 缺失项 | 级别 | 处理 |
|---|---|---|
| 歌曲名、歌手 | `severe` | `--fix` 时可移入 `INCOMPLETE_DIR` |
| 专辑、年份、封面 | 提示 | 只进报告，不移动文件 |

封面判定 `has_cover()` **只认内嵌封面**，不认同目录的 `cover.jpg`：补封面写的是内嵌图，
判定也必须看同一个位置，否则会出现「报告说没有、工具认为已有」的自相矛盾。

支持探测的格式：mp3 / wav / dsf（ID3 `APIC`）、flac（picture block）、ogg / opus
（`metadata_block_picture`）、ape（`Cover Art (Front)`）、m4a（`covr`）、wma（`WM/Picture`）。

扫描阶段 `core.scan.build_track()` 会用 `core/tags.read_meta()` 一次拿到「标签 + 时长 + 封面」，
`missing_tag_fields()` 优先用这个缓存，不再为了一行报告把文件重新解析一遍。

### 2.1 待补全判定

唯一实现：`core/check.py: readiness_problems()`。

- 必须有歌曲名、歌手、专辑、年份；
- 年份必须能解析成 1900–2100 之间的四位数字（`0`、`3013`、`未知` 都不行）；
- 文件名与标签不能矛盾（见第 3 节）；
- **封面、歌词不参与判断**。

任何一项不满足就移入 `INCOMPLETE_DIR`，其余文件留在 `WORKSPACE_DIR`。
这与「标签完整性」不是同一件事：后者用于报告与 `--fix`，前者只决定分流。

年份要单独校验，是因为归档用的 `organize.target_path()` 同样要求年份可解析：
只判「非空」会出现「判定可入库、归档却落进 `unknown/`」的两套结论。

## 3. 文件名与标签一致性

`core/check.py: _consistency_problem()`：

- 歌手：两边都能解析时，拆分多艺术家后做交集；交集为空才算矛盾；
- 歌名：去空白、转小写后比较；完全相同或互为子串不算矛盾；
- 任一侧为空时跳过该维度。

### 3.1 歌手维度是「宽松」的

歌手判定按三条放行规则依次检查，任一命中即视为一致：

| 规则 | 例子 | 为什么 |
|---|---|---|
| 任一侧是占位歌手 | 标签 `Various Artists` / `群星` / `未知艺人` | 合辑里每个文件的标签都是 `Various Artists`，文件名是具体歌手，不是错误 |
| token 有交集 | `周杰伦 & 方文山` vs `周杰伦` | 多艺术家写法不同 |
| token 互为子串 | `周杰伦` vs `周杰伦 (Jay Chou)`、`周杰伦 feat. 杨瑞代` | 别名写在括号里、feat 写在歌手字段里 |

token 由 `core/naming.py: artist_tokens()` 生成，收录三种写法：拆分后的每个歌手、
去掉别名括号的主名、括号里的别名。

这样设计的原因：歌手维度一旦判错就是 `severe`，`--fix` 会把文件搬进 `INCOMPLETE_DIR`。
漏判只是少报一个问题，误判却要人工搬回来——所以宁可宽。

示例：

| 文件名 | 标签 | 结果 |
|---|---|---|
| `周杰伦 - 晴天.flac` | artist=周杰伦, title=晴天 | 一致 |
| `周杰伦 - 晴天.flac` | artist=林俊杰 | 歌手矛盾 |
| `Jay - 晴天.flac` | artist=Jay Chou | 一致（子串） |
| `周杰伦 - 晴天.flac` | artist=周杰伦 (Jay Chou) | 一致（别名） |
| `周杰伦 - 晴天.flac` | artist=Various Artists | 一致（占位歌手） |
| `周杰伦 - 晴天 (Live).flac` | title=晴天 | 一致（子串） |

## 4. 重复判定

唯一实现：`core/dedupe.py`。

### 4.1 两条规则

| 规则 | 键 | 说明 |
|---|---|---|
| 标签维度 | `歌手 + 歌名`（版本感知） | 两个字段都取自标签；歌名为空则跳过 |
| 文件名维度 | 去掉下载序号的文件名主干 | 保留 `(Live)` 等版本括号 |

两条规则都要求**时长差 ≤ `DURATION_TOLERANCE`**（默认 3 秒）。
该阈值的唯一来源是 `config.py`，`core/dedupe.py` 不再自带一份默认值。

文件名维度还有三个细节：

1. **归一化**：比较前去掉全部空白并转小写，`Artist - Song` 与 `artist - song` 视为同一主干；
2. **下载序号**：`(1)`、`（2）` 与 `_1`、`_2` 都算序号。`_n` 是 `Plan` 处理重名时的产物，
   不认它就会留下一批永远查不出来的重复文件；
3. **非规范名只在同目录内比对**：文件名里没有 ` - `（如 `Intro.flac`）时拿不到歌手信息，
   跨目录同名多半是不同专辑里的不同曲目，不能判重；带 ` - ` 的才允许跨目录。

### 4.2 合并顺序

先跑标签维度，再跑文件名维度。文件名组里**已被标签组认领的文件剔除**，剩下的仍有 2 个以上才成组。

不能因为「组里有一个已被认领」就把整组丢掉——否则 A 进了标签组，同名的 B、C 就被吞掉了。

时长读取失败（`duration <= 0`）的曲目并入同名簇，并在组上标记「时长未知」。
这类组**只报告，不自动移动/回收**：读不出时长多半是文件损坏，与同名曲目只是「可能」重复，
交给人工判断。规则见第 7 节。

### 4.3 保留策略

`pick_keep()` 依次比较：

1. 格式优先级：`.flac` / `.dsf` > `.wav` / `.ape` > `.ogg` / `.opus` > `.mp3` / `.m4a` > `.wma` > 其他；
2. 同格式下文件更大者。

其余文件进入 `drop`，由流程决定移入 `DUPLICATE_DIR` 或回收站。

### 4.4 声纹与版本碰撞

`soundalike` 的声纹比对与上面的本地规则是**两条独立信号**：

- 声纹对「同一录音换格式/换专辑」最有效；
- 对 Live、Remix、伴奏、不同歌手同伴奏等场景可能给出高相似度；
- 因此声纹结果不能覆盖版本标记。版本标记不同的候选应转人工，不自动移入 `DUPLICATE_DIR`。

完整的碰撞场景与处理策略见 [fingerprint.md](fingerprint.md#6-同曲不同版本的碰撞)。

## 5. 歌词规则

唯一实现：`core/lyrics.py`。

- 歌词文件与音频**同目录、同主文件名**，扩展名 `.lrc`；
- `missing_lrc()` 找出没有同名 `.lrc` 的曲目；
- `orphan_lrc()` 找出没有对应音频的 `.lrc`（按 `config.AUDIO_EXTENSIONS` 判断）；
- 音频移动/改名时，`core.ops.Plan` 会同步搬运同名 `.lrc`。

## 6. 归档规则

唯一实现：`core/organize.py`。

### 6.1 年代标签

`decade_label(year)`：

| 年份 | 目录 |
|---|---|
| ≤ 1979 | `1950-1979` |
| 1980–1989 | `1980-1989` |
| 1990–1999 | `1990-1999` |
| 2000–2009 | `2000-2009` |
| … | 依次类推 |

年份从标签里提取四位数字，合法范围为 1900–2100。

### 6.2 目标路径

```
<目标根>/<年代>/<年份>/<文件名>
```

归档要求歌曲名、歌手、年份齐全；缺少任一项的文件进入 `<目标根>/unknown/`。
注意待补全判定还要求专辑，所以正常情况下进入归档的文件已经满足这些字段。

## 7. 修复范围

`--fix` / 流水线检查阶段的动作严格限制为：

| 动作 | 条件 |
|---|---|
| 重复文件进回收站 | 显式 `--trash-dup`，且该组「时长未知」为假 |
| 重复文件移入 `DUPLICATE_DIR` | 未显式回收时，条件同上 |
| 移入 `INCOMPLETE_DIR` | 仅 `severe`：歌曲名/歌手缺失、文件名与标签矛盾 |
| 文件名分隔符规范化 | 单个 `-` 且可安全改写 |
| 按标签补全文件名 | 文件名没有「歌手 - 歌名」结构、且标签齐全且不与文件名矛盾 |
| 改名/移动其余文件 | **不做** |

缺封面、缺专辑、缺年份只写报告，不移动文件——否则一次 `--fix` 可能搬空整个库。

### 7.1 按标签补全文件名的边界

`plan_fixes(rename_by_tags=...)` 控制这一项，默认关闭：

- `--check --fix` 与主流水线开启：它们本来就读了标签；
- `--only-check-file-name --fix` 关闭：它只读文件名，没有可信的标签可用。

只在该文件「标签齐全且与现有文件名不矛盾」时才按标签改名。
标签本身自相矛盾时按标签改，等于把错的那份写到文件名上。

### 7.2 改名撞车一律失败

目标文件名已存在时，`core.ops.Plan` **不会**自动加 `_1` 后缀，而是记一条失败：

```
[rename] A-B.flac -> A - B.flac  # 失败: 目标已存在，拒绝改名以免产生重复
```

静默加后缀会造出一个「看起来正常、实际是重复」的文件，而它又不在查重规则里，
只能靠人发现。失败记录进 `log/journal.jsonl`，源文件保持原样，下一轮仍然可见。

移动（`move`）撞车仍按 `_1`、`_2` 递增：移动是「必须放下」的动作，
而改名是「名字要更正确」，两者取舍不同。

## 8. 报告

唯一实现：`core/report.py`，由 `core/check.py: report_into()` 填充。

- Markdown：汇总各检查项数量，附明细表；
- CSV：待处理清单，列为「类型 / 文件 / 说明」；
- 报告写到 `--report-dir` 或默认 `log/reports/`；
- 报告只描述检查结果，不代替 `log/journal.jsonl` 的实际动作流水。
