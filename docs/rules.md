# 判定规则总表

> 本文是**全项目规则的唯一说明书**：文件名、标签、自检、去重、音质、归档、执行安全、报告，
> 全部集中在这里。代码里每条规则只有一个实现，本文负责说清「为什么这样判」与「边界在哪」。
>
> 本文不负责：流程顺序（见 [workflow.md](workflow.md)）、Web 界面操作（见
> [web-guide.md](web-guide.md)）、命令行参数（见 [usage.md](usage.md)）、阈值配置位置
> （见 [configuration.md](configuration.md)）。

三条约定贯穿全文：

1. **一条规则只实现一次**。改规则要改对应模块并补 `tests/` 用例，不要在调用方再写一遍判断。
2. **宁可漏判，不做误判**。漏判只是少报一个问题，误判会让人去把文件搬回来。
3. **拿不准就转人工**。规格读不出、时长对不上、标签互相矛盾——一律标"需人工"，不自动处理。

## 1. 文件名规则

### 1.1 规范格式

```
<歌手> - <歌名>.<扩展名>
```

`is_canonical()` 要求同时满足：能解析出歌手、能解析出歌名、含 ` - `（空格-空格）。

### 1.2 解析

`parse_filename()` 的优先级：

1. 先按第一个 ` - ` 分割；
2. 没有 ` - ` 时按第一个 `-` 分割；
3. 都没有时歌手为空、整段作为歌名。

### 1.3 规范化

`canonicalize()` **只**在「恰好一个 `-` 且没有 ` - `」时把分隔符改成 ` - `：

| 原名 | 结果 |
|---|---|
| `周杰伦-晴天.flac` | `周杰伦 - 晴天.flac` |
| `AC-DC - Back.flac` | 不改（已经有 ` - `） |
| `A-B-C.flac` | 不改（多个 `-`，可能是名字本身） |

`format_filename()` 会清理 `\ / : * ? " < > |` 等非法字符，并按需拼接扩展名。
清理是按字符替换，不做转义——这些字符在 Windows 上根本不允许出现在文件名里。

### 1.4 版本标记

`version_markers()` 从**括号内容**里识别版本类别：

| 类别 | 同义词 |
|---|---|
| `live` | live、现场、演唱会、concert |
| `remix` | remix、混音、dj、bootleg、rework |
| `instrumental` | instrumental、伴奏、karaoke、offvocal、纯音乐 |
| `acoustic` | acoustic、unplugged、不插电 |
| `demo` | demo、小样、session、outtake、未发行 |
| `cover` | cover、翻唱 |
| `feat` | feat、featuring、ft.、ft |

`version_key()` 保留这些标记，只去掉下载序号与其他无关括号：

| 输入 | 去重键 |
|---|---|
| `晴天` | `晴天` |
| `晴天 (1)` | `晴天` |
| `晴天 (Live)` | `晴天\|live` |
| `晴天（现场版）` | `晴天\|live` |

去重键由 `Track.key` 使用，因此 Live/Remix/伴奏版不会因为名字相似被直接当成同一首。

### 1.5 归一化

`normalize_text()` 去全部空白并转小写，用于「忽略大小写与空格」的比较；
`normalize_key()` 进一步去掉标点，用于更宽松的匹配。两者都只做字符串处理，不猜内容。

### 1.6 音频扩展名

`config.AUDIO_EXTENSIONS` 决定「什么算音频」：flac / mp3 / wav / ape / ogg / opus /
m4a / wma / dsf。

裸 `.aac`（ADTS）**刻意不在内**：它没有统一的容器标签，读不出歌手/歌名，纳入扫描只会让
整个库突然"缺标签"。加密格式（mflac / mgg / ncm）只出现在第 4 步的解密来源里。

## 2. 标签规则

### 2.1 字段与容器映射

`core/tags.py` 统一五个字段：歌曲名 / 歌手 / 专辑 / 年份 / 流派（`title` `artist`
`album` `year` `genre`），按容器走不同键名：

| 容器 | 歌曲名 | 歌手 | 专辑 | 年份 | 流派 |
|---|---|---|---|---|---|
| mp3 / wav / dsf（ID3） | `TIT2` | `TPE1` | `TALB` | `TDRC` | `TCON` |
| flac / ogg / opus（Vorbis） | `title` | `artist` | `album` | `date` | `genre` |
| ape（APEv2） | `Title` | `Artist` | `Album` | `Year` | `Genre` |
| m4a（MP4） | `©nam` | `©ART` | `©alb` | `©day` | `©gen` |
| wma（ASF） | `Title` | `Author` | `WM/AlbumTitle` | `WM/Year` | `WM/Genre` |

年份统一归一成四位数字字符串；读不出合法年份时留空，不猜。

### 2.2 完整性检查

`missing_tag_fields()` 检查五个字段，返回缺失项的中文名。严重级别只在检查阶段使用：

| 缺失项 | 级别 | 处理 |
|---|---|---|
| 歌曲名、歌手 | `severe` | `--fix` 时可移入 `INCOMPLETE_DIR` |
| 专辑、年份、封面 | 提示 | 只进报告，不移动文件 |

封面判定 `has_cover()` **只认内嵌封面**，不认同目录的 `cover.jpg`：补封面写的是内嵌图，
判定也必须看同一个位置，否则会出现「报告说没有、工具认为已有」的自相矛盾。

### 2.3 可入库判定

`readiness_problems()` 决定一个文件能不能往库里归档：

- 必须有歌曲名、歌手、专辑、年份；
- 年份必须能解析成 1900–2100 之间的四位数字（`0`、`3013`、`未知` 都不行）；
- 文件名与标签不能矛盾（见第 3 节）；
- **封面、歌词不参与判断**。

年份要单独校验，是因为归档用的 `target_path()` 同样要求年份可解析：只判「非空」会出现
「判定可入库、归档却落进 `unknown/`」的两套结论。

### 2.4 标签来源与优先级

`Tagger.update()` 的顺序是**固定**的，不做多源投票：

| 顺序 | 来源 | 条件 | 失败时 |
|---|---|---|---|
| 1 | 声纹（MusicBrainz / AcoustID） | 有 fpcalc 且得分 ≥ `FINGERPRINT_THRESHOLD`（默认 50） | 静默降级到第 2 步 |
| 2 | QQ 音乐 + 网易云 | 用「标签里的歌名歌手」或「文件名解析出的歌名歌手」查询 | 两者都失败则只保留原有标签 |
| — | 文件名 | **只用来查询**，永远不直接写进标签 | — |

声纹命中就不再问在线平台：声纹是「按音频本身比对」，比标题搜索可靠，两者结论冲突时
以声纹为准。只有一个例外——在线平台已拿到满分 100（见 2.5）时提前结束，省一次往返。

### 2.5 平台择优打分

`core/scoring.py: tag_score()`，满分 100：

| 项 | 分值 |
|---|---|
| 每个非空字段 | 歌曲名 10 / 歌手 10 / 专辑 10 / 年份 5 / 流派 5 |
| 歌曲名完全一致 / 互相包含 | 30 / 20 |
| 歌手匹配（多歌手取最高分） | 30 |

### 2.6 平台候选过滤

两个平台返回的都是列表，取第一条通过过滤的记录：

1. **歌手匹配**：查询歌手拆成多个名字后，任一与在线歌手互为子串即通过；查询歌手为空时直接通过。
2. **标题匹配**：本地歌名与在线歌名互为子串。

二者都过才采信——只对歌名不看歌手，会把翻唱当原唱。

### 2.7 合并与写入

`_merge()`：**已有标签优先，只填空缺**。已有值不会被远程结果覆盖，哪怕是错的——批量流程
里"纠正错标签"是手工活，第 5 步的单曲编辑才是它的入口。

写入时只写「在白名单内、且与当前值不同」的字段：

- 白名单来自 `Tagger(fields=...)`，Web 第 5 步的字段开关就是它；
- 白名单外字段既不查询也不写入，避免"我只想补年份，结果专辑被改了"。

### 2.8 封面规则

- 来源：MusicBrainz → Cover Art Archive `front-500`；QQ 音乐 → 300×300 专辑图；
- 大小上限 `MAX_COVER_SIZE`（默认 5 MB），超限直接放弃，不截断；
- **已有内嵌封面时不覆盖**；
- 只写内嵌图（ID3 `APIC` / FLAC picture block / Vorbis `metadata_block_picture` /
  APE `Cover Art (Front)` / MP4 `covr` / ASF `WM/Picture`）。

### 2.9 歌词规则

- 歌词文件与音频**同目录、同主文件名**，扩展名 `.lrc`；
- `missing_lrc()` 找出没有同名 `.lrc` 的曲目；
- `orphan_lrc()` 找出没有对应音频的 `.lrc`（按 `config.AUDIO_EXTENSIONS` 判断）；
- **已有 `.lrc` 不覆盖**；
- QQ 音乐同时返回原文与翻译时，写成「原文 + 空行 + `[翻译]` + 译文」；
- 音频移动/改名时，`core.ops.Plan` 会同步搬运同名 `.lrc`（搬歌词失败不影响主文件）。

### 2.10 单曲手工编辑

`services/steps.py: save_track()`：

- 只写传入的字段，**不改文件名**——改名牵动重复判定、归档路径与 journal，属于归档环节；
- 空字符串表示"不改"，原值保留（不会被清空）；
- 值没变化就不写盘，返回 `changed` 为空；
- 歌词传 `None` 表示不动，传字符串则整体覆盖。

在线取标签（`fetch_track_online`）默认 `dry_run=True`：只返回合并后的值给页面预览，
用户确认后才由 `save_track` 落盘，避免"点一下就把标签改了"。

## 3. 文件名与标签一致性

### 3.1 三态结论

`core/check.py: consistency_report()` 对两个维度分别给出：

| state | 含义 | 是否算问题 |
|---|---|---|
| `ok` | 一致 | 否 |
| `mismatch` | 矛盾 | **是** |
| `skipped` | 该维度不可比（文件名没有歌手结构、标签为空、群星合辑） | 否 |

`skipped` 的存在是为了不把"标签还没填"误报成"标签写错"。只有 `mismatch` 会进
`readiness_problems()`，也才会被页面标红。

### 3.2 歌手维度是「宽松」的

`_artist_conflict()` 依次检查三条放行规则，任一命中即视为一致：

| 规则 | 例子 | 为什么 |
|---|---|---|
| 任一侧是占位歌手 | 标签 `Various Artists` / `群星` / `未知艺人` | 合辑里每个文件的标签都是 `Various Artists`，文件名是具体歌手，不是错误 |
| token 有交集 | `周杰伦 & 方文山` vs `周杰伦` | 多艺术家写法不同 |
| token 互为子串 | `周杰伦` vs `周杰伦 (Jay Chou)`、`周杰伦 feat. 杨瑞代` | 别名写在括号里、feat 写在歌手字段里 |

token 由 `core/naming.py: artist_tokens()` 生成，收录三种写法：拆分后的每个歌手、去掉别名
括号的主名、括号里的别名。

歌手维度一旦判错就是 `severe`，`--fix` 会把文件搬进 `INCOMPLETE_DIR`。漏判只是少报一个
问题，误判却要人工搬回来——所以宁可宽。

### 3.3 歌名维度

去空白、转小写后比较：完全相同或互为子串都算一致（`晴天` vs `晴天 (Live)`）。

### 3.4 示例

| 文件名 | 标签 | 结果 |
|---|---|---|
| `周杰伦 - 晴天.flac` | artist=周杰伦, title=晴天 | 一致 |
| `周杰伦 - 晴天.flac` | artist=林俊杰 | 歌手矛盾 |
| `Jay - 晴天.flac` | artist=Jay Chou | 一致（子串） |
| `周杰伦 - 晴天.flac` | artist=周杰伦 (Jay Chou) | 一致（别名） |
| `周杰伦 - 晴天.flac` | artist=Various Artists | 一致（占位歌手） |
| `周杰伦 - 晴天 (Live).flac` | title=晴天 | 一致（子串） |
| `Intro.flac` | title=Intro, artist=某某 | 歌手维度 skipped |

## 4. 自检规则

唯一实现：`core/check.py: check_library()`。工作区自检（第 7 步）与库自检用的是同一份代码，
只是范围与开关不同。

### 4.1 六类检查项

| 常量 | 中文 | 判定 | 严重 |
|---|---|---|---|
| `KIND_FILENAME` | 文件名格式 | 不满足 `is_canonical()`，且 `canonicalize()` 能给出建议 | 否 |
| `KIND_MISMATCH` | 文件名与标签不一致 | 第 3 节判为 `mismatch` | **是** |
| `KIND_TAGS` | 标签不完整 | 缺歌曲名 / 歌手 | **是** |
| `KIND_DUP` | 重复文件 | 第 5 节集合内查重命中 | 否（但会移动） |
| `KIND_NO_LRC` | 缺少歌词 | 无同名 `.lrc` | 否 |
| `KIND_ORPHAN_LRC` | 孤立歌词 | `.lrc` 没有对应音频 | 否 |

`fixable` 表示该项有自动修复动作；`severe` 表示可以移入 `INCOMPLETE_DIR`。

### 4.2 修复范围（`--fix` 白名单）

动作严格限制为：

| 动作 | 条件 |
|---|---|
| 重复文件进回收站 | 显式 `--trash-dup`，且该组「时长未知」为假 |
| 重复文件移入 `DUPLICATE_DIR` | 未显式回收时，条件同上 |
| 移入 `INCOMPLETE_DIR` | 仅 `severe`：歌曲名/歌手缺失、文件名与标签矛盾 |
| 文件名分隔符规范化 | 单个 `-` 且可安全改写 |
| 按标签补全文件名 | 文件名没有「歌手 - 歌名」结构、且标签齐全且不与文件名矛盾 |
| 改名/移动其余文件 | **不做** |

缺封面、缺专辑、缺年份只写报告，不移动文件——否则一次 `--fix` 可能搬空整个库。

### 4.3 按标签补全文件名的边界

`plan_fixes(rename_by_tags=...)` 控制这一项，默认关闭：

- `--check --fix` 与主流水线开启：它们本来就读了标签；
- `--only-check-file-name --fix` 关闭：它只读文件名，没有可信的标签可用。

只在该文件「标签齐全且与现有文件名不矛盾」时才按标签改名。标签本身自相矛盾时按标签改，
等于把错的那份写到文件名上。

### 4.4 改名撞车一律失败

目标文件名已存在时，`Plan` **不会**自动加 `_1` 后缀，而是记一条失败：

```
[rename] A-B.flac -> A - B.flac  # 失败: 目标已存在，拒绝改名以免产生重复
```

静默加后缀会造出一个「看起来正常、实际是重复」的文件，而它又不在查重规则里，只能靠人发现。
失败记录进 `log/journal.jsonl`，源文件保持原样，下一轮仍然可见。

移动（`move`）撞车仍按 `_1`、`_2` 递增：移动是「必须放下」的动作，而改名是「名字要更正确」，
两者取舍不同。唯一的例外是只改大小写的改名——目标就是它自己，不算撞车。

## 5. 去重规则

唯一实现：`core/dedupe.py`。这里有**两种**查重，规则不同，不能混用：

| | 集合内查重 | 跨集合查重 |
|---|---|---|
| 入口 | `find_duplicates()` | `match_against()` |
| 问题 | 这一堆文件里哪些互为重复 | 这批新文件库里是不是已经有了 |
| 要回答 | 留哪个、移走哪些 | 能不能入库；库里那份要不要让位 |
| 用在哪 | `--check`、声纹去重 | 第 6 步 |

### 5.1 集合内：两条维度

| 规则 | 键 | 说明 |
|---|---|---|
| 标签维度 | `歌手 + 歌名`（版本感知） | 两个字段都取自标签；歌名为空则跳过 |
| 文件名维度 | 去掉下载序号的文件名主干 | 保留 `(Live)` 等版本括号 |

两条规则都要求**时长差 ≤ `DURATION_TOLERANCE`**（默认 3 秒）。该阈值的唯一来源是
`config.py`，`core/dedupe.py` 不再自带一份默认值。

文件名维度还有三个细节：

1. **归一化**：比较前去掉全部空白并转小写，`Artist - Song` 与 `artist - song` 视为同一主干；
2. **下载序号**：`(1)`、`（2）` 与 `_1`、`_2` 都算序号。`_n` 是 `Plan` 处理重名时的产物，
   不认它就会留下一批永远查不出来的重复文件；
3. **非规范名只在同目录内比对**：文件名里没有 ` - `（如 `Intro.flac`）时拿不到歌手信息，
   跨目录同名多半是不同专辑里的不同曲目，不能判重；带 ` - ` 的才允许跨目录。

### 5.2 集合内：合并顺序

先跑标签维度，再跑文件名维度。文件名组里**已被标签组认领的文件剔除**，剩下的仍有 2 个以上
才成组。不能因为「组里有一个已被认领」就把整组丢掉——否则 A 进了标签组，同名的 B、C 就被吞掉了。

时长读取失败（`duration <= 0`）的曲目并入同名簇，并在组上标记「时长未知」。这类组**只报告，
不自动移动/回收**：读不出时长多半是文件损坏，与同名曲目只是「可能」重复，交给人工判断。

### 5.3 集合内：保留策略

`pick_keep()` 依次比较：

1. 格式优先级：`.flac` / `.dsf` > `.wav` / `.ape` > `.ogg` / `.opus` > `.mp3` / `.m4a` > `.wma` > 其他；
2. 同格式下文件更大者。

其余文件进入 `drop`，由流程决定移入 `DUPLICATE_DIR` 或回收站。

> 这里的"更大者"只用于**同格式内部**（同格式大 = 码率/位深更高）。跨格式时不看体积，
> 见第 6.5 节的格式偏好。

### 5.4 跨集合：先确认是同一录音

```
歌手 + 歌名 相同  →  候选
候选里逐条判断「是不是同一个录音」：
    文件大小完全相同        →  是（同一文件的复制/移动，字节数一定相同）
    否则 时长差 ≤ 3 秒      →  是
    两者都拿不到            →  None（转人工）
```

判定顺序不能反：库索引为了性能不读时长（见 5.6），先比大小能在绝大多数情况下直接命中。

标签维度没有候选时，退到文件名维度，且与集合内规则一致：必须带 ` - ` 结构才跨目录比对。

### 5.5 跨集合：四种结论

确认是同一录音后，用第 6 节比音质：

| status | 条件 | 动作 | 页面标签 |
|---|---|---|---|
| `unique` | 库里没有同名/同歌手+歌名的曲目，或同名但大小与时长都不一致 | 照常归档 | 库中不存在 |
| `duplicate` | 库里已有**同等或更好**的版本 | 移走**工作区**这份 | 库中已有 |
| `upgrade` | 库里那份**更差**（音质更低，或同音质但更占地方） | 移走**库里**那份，工作区这份归档 | 可替换库内 |
| `unknown` | 大小与时长都无法确认，或音质规格读不出来 | 什么都不做 | 需人工确认 |

`upgrade` 还有两种依据，页面必须区分，不能用"音质升级"一词盖过：

| basis | 含义 | 依据 |
|---|---|---|
| `quality` | 库里那份音质确实更低 | 无损/有损、采样率、位深、码率 |
| `format` | 音质完全一致，但库里那份格式更占磁盘 | 同规格 WAV vs FLAC/APE |

### 5.6 跨集合：一对多

一个工作区文件可能对上库里**多个**文件（同一首的不同版本、不同年份目录里的副本）。
规则：

- `matched` 与 `comparisons` **全部返回**（上限 50 条，多余的在 `matched_total` 里计数）；
- 页面用左右两栏展示，右栏逐条列出，**替换哪几个由用户勾选**；
- 执行时通过 `replaces` 传 `{工作区路径: [库内路径...]}`，未传的路径一律拒绝——
  不允许借这个接口去动预览里没有列出的库内文件；
- 一个 `upgrade` 项如果库内文件全被取消勾选，该项整项不做处理（工作区与库都保持原样）。

### 5.7 跨集合：执行边界

这是全项目唯一会动**库目录存量文件**的流程，所以边界比别处多：

| 边界 | 规则 |
|---|---|
| 必须逐条指定 | `statuses` 含 `upgrade` 时 `paths` 不能为空，否则直接报错 |
| `replaces` 只能收窄 | 只能从预览里列出的可替换文件中选择，伪造路径报错 |
| 库内文件永不删除 | `upgrade` 移走库内文件时**无论** `action` 是什么，都进 `DUPLICATE_DIR` |
| 工作区文件两种落点 | CLI 默认进 `DUPLICATE_DIR`；网页上用户明确点「删除」才进回收站 |
| `unknown` 不处理 | 即使被勾选也会被过滤掉 |

命令行与网页的差异：

| | 命令行 | 网页（第 6 步） |
|---|---|---|
| 工作区重复文件 | 移入 `DUPLICATE_DIR`（`--trash-dup` 才进回收站） | 默认「删除」→ 回收站，也可选移入重复目录 |
| 库内旧版本 | 移入 `DUPLICATE_DIR` | 同上，且必须逐条确认 |
| 确认方式 | 参数与 dry-run 预览 | 两栏列表 + 弹出确认框 |

### 5.8 声纹与版本碰撞

`soundalike` 的声纹比对与上面的本地规则是**两条独立信号**：

- 声纹对「同一录音换格式/换专辑」最有效；
- 对 Live、Remix、伴奏、不同歌手同伴奏等场景可能给出高相似度；
- 因此声纹结果不能覆盖版本标记。版本标记不同的候选应转人工，不自动移入 `DUPLICATE_DIR`。

完整的碰撞场景与处理策略见 [fingerprint.md](fingerprint.md#6-同曲不同版本的碰撞)。

## 6. 音质比较规则

唯一实现：`core/quality.py`。这条规则只回答一个问题：**同一个录音的两份文件，哪一份更值得留下。**

### 6.1 两层判定

```
1. 无损 / 有损        → 无损永远更好
2. 同一层内部
      无损：比 (采样率, 位深)，字典序
      有损：比码率
```

无损集合：`.flac .ape .wav .dsf .dff .aif .aiff .alac`。
其余扩展名按有损处理。

### 6.2 无损比规格

`(sample_rate, bit_depth)` 元组直接比较：

| 左 | 右 | 结论 |
|---|---|---|
| 96kHz/24bit | 44.1kHz/16bit | 更好 |
| 48kHz/24bit | 96kHz/24bit | 更差 |
| 44.1kHz/16bit | 44.1kHz/16bit | 相同 |

任一侧读不出采样率或位深 → `unknown`，不猜。

### 6.3 有损比码率

- 优先用容器报的码率；
- 容器不报（部分 m4a / ogg）时用 `大小 × 8 ÷ 时长` 估算；
- 相对差在 `BITRATE_TOLERANCE`（10%）以内视为**同一水平**——同一次转码的不同产物不该互相替换。

### 6.4 读不出来时

规格读不出来（损坏、容器不被 mutagen 支持、文件被占用）时：

- `compare()` 返回 `unknown`；
- 若两份**格式相同**，跨集合查重会把它降级成 `same`（同格式同录音没有可靠的升级依据，保守不动库）；
- 格式不同还读不出来，说明连无损/有损都判不了，保留 `unknown` 转人工。

### 6.5 格式偏好：同音质时留省磁盘的那份

`storage_preference()`，**只在 `compare()` 已判 `same` 之后调用**。此时采样率与位深完全一致，
解码出来是同一串 PCM，唯一差别是容器：

| 左 | 右 | 结论 |
|---|---|---|
| FLAC / APE / ALAC | WAV / AIFF | 更好（体积约为一半） |
| WAV / AIFF | FLAC / APE / ALAC | 更差 |
| FLAC | APE | 相同（都是压缩无损，转换无收益） |
| 任一 DSD（dsf/dff） | 任意 | 相同（DSD 转 PCM 本身就不是无损） |

命中「更好」时，跨集合查重会把结论升级为 `upgrade` 且 `basis='format'`。
页面上它显示为「同音质更省磁盘」，**不能**说成音质升级——两者的用户预期完全不同。

### 6.6 为什么不用文件大小

WAV 未压缩，同源体积一定是 FLAC 的两倍，但音质完全等同；反过来低码率 MP3 也可能比高压缩的
FLAC 大。只看体积会同时犯两类错：把 WAV 当更好的留下、把大文件的 MP3 当成升级。
体积只在两个地方有意义：同格式内部比码率（5.3）、同音质跨容器时比占用（6.5）。

## 7. 归档规则

唯一实现：`core/organize.py`。

### 7.1 年代标签

`decade_label(year)`：

| 年份 | 目录 |
|---|---|
| ≤ 1979 | `1950-1979` |
| 1980–1989 | `1980-1989` |
| 1990–1999 | `1990-1999` |
| 2000–2009 | `2000-2009` |
| … | 依次类推 |

年份从标签里提取四位数字，合法范围为 1900–2100。

### 7.2 目标路径

```
<目标根>/<年代>/<年份>/<歌手> - <歌名>.<扩展名>
```

归档要求歌曲名、歌手、年份齐全；缺少任一项的文件进入 `<目标根>/unknown/`。
注意可入库判定还要求专辑，所以正常情况下进入归档的文件已经满足这些字段。

第 8 步可以选择目标根：入库 → `LIBRARY_DIR`；只整理 → `WORKSPACE_DIR`。

## 8. 执行与安全规则

### 8.1 唯一出口

所有写盘动作（移动、改名、删除）只能经 `core.ops.Plan` 发出。`core/` 其他模块一律无副作用，
`services/` 负责编排，`web/` 只做参数校验与序列化。

### 8.2 三种动作的语义

| 动作 | 目标 | 撞车时 |
|---|---|---|
| `move` | 指定路径 | 加 `_1`、`_2` 递增 |
| `rename` | 同目录新名字 | 目标存在则**失败**，不自动加后缀 |
| `trash` | `TRASH_DIR` | 加 `_1` 递增；未配置回收站目录则拒绝执行 |

源文件不存在时记 `skipped`，不算失败。单条操作失败不影响整批，逐条记入 journal。

### 8.3 留痕

- 每条操作写 `log/journal.jsonl`：时间、计划名、动作、源、目标、结果、原因；
- 删除只是移动到 `log/_trash`，可人工找回；
- `--dry-run` 时 `execute()` 把所有操作标为 `skipped`，一个字节都不动。

### 8.4 同名歌词

音频移动或改名时，同名 `.lrc` 跟着走。搬歌词失败只吞掉异常，不影响主文件——主文件的正确
位置比歌词更重要，歌词下一轮还能补。

### 8.5 Web 的路径安全

- 第 5 步的单曲编辑：路径必须落在 `WORKSPACE_DIR` 内、必须是音频、必须存在（`_audio_in_workspace()`）；
- 第 6 步的执行：`paths` 逐条列出，`replaces` 只能收窄，二者有交集校验；
- 目录设置：只接受绝对路径，Windows 用 `os.name == 'nt'` 判断平台，不用 `sys.platform`
  （Windows 上是 `'win32'`，写成 `'nt'` 会永远为假）。

### 8.6 缓存失效

两条缓存，都只在「库目录或配置变了」时清空：

| 缓存 | 内容 | 失效时机 |
|---|---|---|
| `_library_cache` | 库目录索引（路径 / 大小 / 文件名解析出的标签） | `invalidate_library_cache()`、`refresh=True` |
| `_quality_cache` | 按需读出的音频规格 | 同上 |

库索引只做 `os.walk + stat + parse_filename()`，不读标签。一万两千首实测约 3 秒；改成逐个
`read_tags()` 要十几分钟，而查重只需要「歌手 + 歌名 + 大小」三项——库里文件的文件名是归档
流程自己按「歌手 - 歌名.ext」写进去的，本身就是可信来源。

## 9. 报告规则

唯一实现：`core/report.py`，由 `core/check.py: report_into()` 填充。

- Markdown：汇总各检查项数量，附明细表；
- CSV：待处理清单，列为「类型 / 文件 / 说明」；
- 报告写到 `--report-dir` 或默认 `log/reports/`；
- 报告只描述检查结果，不代替 `log/journal.jsonl` 的实际动作流水。

## 10. 改规则的步骤

1. 找到第 0 节表格里对应的唯一实现；
2. 改代码，不新增第二份判断；
3. 在 `tests/` 补用例，尤其是"这条规则**不该**触发的边界"；
4. 回来改本文对应小节，别让文档和代码各说一套；
5. `python scripts/check_docs.py` 确认没有死链与过期路径。
