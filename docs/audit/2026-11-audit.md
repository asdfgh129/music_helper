## 二、遗留清单（记录在案，见 next-steps.md）

### 性能 P1（行为不变，可逐项落地）

1. `run_fill_tags` 同批文件标签读两遍（`tag_candidates` 全扫 + 循环内再 `build_track`）
2. `run_archive` 三次全量扫描工作区（preview / dedupe 闸门 / 执行各一次）
3. `flow_manual_archive` 三次扫描 + 每文件 `readiness_problems` 算 4 次
4. `check_library` 孤立歌词检查触发第二次全库目录遍历（`orphan_lrc` 独立 walk）
5. 封面接口每次请求重新解析文件且 `no-store` 禁缓存（可加按 `(path, mtime)` LRU + ETag）
6. 直接解密逐文件起 um 子进程（可批量，省进程启动开销）
7. 声纹池以 int tuple 常驻内存 ≈ 100 MB/万首（可存 bytes，配合 P0-2 大整数方案）
8. `POST /api/check` 每次全量重扫，`_last_check` 无失效机制（兼正确性隐患）

### 安全 P2

- `/api/fs/list` 可列出本机任意目录（信息收集原语；docstring 已声明口径，
  S1 修复后跨站风险已消，纯本机场景可接受，远程监听时建议收敛到快捷目录树）
- Web 无鉴权 token：绑定非 127.0.0.1 时同网段设备可直接调用（与 S1 中间件
  组合后仅剩「主动暴露」场景，建议文档强调 + 可选 token）
